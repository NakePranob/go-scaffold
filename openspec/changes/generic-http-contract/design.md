# Design

## Context

See `proposal.md` for motivation. The generated API already has a generic
error *envelope*: `apperror.AppError` carries an HTTP status, a machine code,
a public message, optional details, and a request ID; `middleware.Error`
renders it once. The gap is everything around that envelope:

- domain sentinels are translated by a hand-written switch in every module;
- auth and RBAC translate their own `RuleError` codes with two different
  switches;
- success responses are written at each call site, so there is no single place
  that owns status codes or the list envelope;
- the method generator compensates for the inconsistent mapper names by
  matching `func <name>(err error) error` at patch time.

The current wire format is already consumed by the Next.js and SvelteKit FSD
templates: errors are `{error:{code,message,details?,request_id?}}`, lists are
`{data,limit,offset,total}`, and single resources are bare objects. The design
keeps those shapes.

## Goals / Non-Goals

**Goals:**

- One success-response writer for generated inbound adapters.
- One domain-error translator with per-module policy declared as data.
- One function name and signature for error mapping across modules, auth, and
  RBAC, so `generate method` does not need to discover it by regex.
- Keep every existing wire shape, status code, JSON field, route, and feature
  flag unchanged.
- Prove the behaviour with an executable QA gate, not source inspection alone.

**Non-Goals:**

- A uniform `{data, meta}` success envelope.
- A CLI `--json` output contract.
- Changing auth/MFA/RBAC response fields or adding new error codes.
- Automatically rewriting projects generated by older CLI versions.

## Decisions

### 1. Keep the wire contract, centralize the writer

The contract is:

| Case | Status | Body |
| --- | --- | --- |
| Single resource (get/update/create) | 200 / 201 | the resource object |
| Delete and other empty success | 204 | empty |
| List | 200 | `{data, limit, offset, total}` |
| Any failure | 4xx/5xx | `{error:{code,message,details?,request_id?}}` |

`internal/shared/httpx` becomes the only package generated inbound adapters
use to write a success:

```go
func OK(c *gin.Context, data any)      { c.JSON(http.StatusOK, data) }
func Created(c *gin.Context, data any) { c.JSON(http.StatusCreated, data) }
func NoContent(c *gin.Context)         { c.Status(http.StatusNoContent) }
func Page(c *gin.Context, p pagination.Params, data any, total int64) {
    c.JSON(http.StatusOK, p.ResponseWithTotal(data, total))
}
```

`httpx` already exists and is imported by handlers; importing
`internal/shared/pagination` from it creates a shared-to-shared dependency, not
a cycle (`pagination` imports only Gin). The alternative — putting `Page` on
`pagination` and leaving status codes in handlers — keeps the per-call-site
status decision that this change is trying to remove.

**Why not a single `{data}` envelope?** It would change auth token responses,
MFA challenge responses, and both FSD clients in the same change. That is a
cross-scaffold breaking decision, not a genericity cleanup. It stays a separate
proposal.

### 2. Translate errors with rules, not switches

`apperror` gains:

```go
type Rule struct {
    Err     error
    Status  int
    Code    string
    Message string
}

func Translate(err error, rules ...Rule) error
```

Behaviour, in order:

1. `nil` → `nil`.
2. `errors.As(err, **AppError)` → return the existing error unchanged.
3. First rule whose `Err` matches via `errors.Is` → `New(rule.Status, rule.Code, rule.Message)`.
4. Otherwise → `NewInternal(err)`, preserving the cause for the middleware log.

A generated module declares its policy in the inbound adapter:

```go
var httpErrors = []apperror.Rule{
    {Err: domain.ErrNotFound, Status: http.StatusNotFound, Code: "ORDER_NOT_FOUND", Message: "order not found"},
    {Err: domain.ErrConflict, Status: http.StatusConflict, Code: "ORDER_CONFLICT", Message: "order already exists"},
    // ...
}

func appError(err error) error { return apperror.Translate(err, httpErrors...) }
```

Domain code stays free of `net/http` and Gin. The HTTP status and public code
live in the inbound adapter, which is the only layer allowed to know them.

**Auth and RBAC:** their `RuleError` already carries a machine code and a
public message. They keep a small `httpStatusForCode` table, then call
`apperror.New` and `apperror.Translate` for the rest; there is one `appError`
function per module and no `toHTTPError` switch. The QA check requires
`apperror.Translate` in the generated `handler.go` and rejects a remaining
`func toHTTPError`.

**Alternative considered:** make domain errors implement an interface that
returns status/code. Rejected because it moves HTTP knowledge into the domain
package, which `go-scaffold check` explicitly forbids.

**Alternative considered:** a `map[error]Mapping`. Rejected because map
iteration makes precedence between overlapping sentinels nondeterministic; a
slice of rules is ordered and explicit.

### 3. Make the generator emit one shape

- `generate module` emits `httpErrors` and a one-line `appError` wrapper, and
  uses `httpx.*` in create/list/get/update/delete.
- `generate method` emits `httpx.NoContent` / `httpx.OK` as appropriate and
  calls the module's `appError`. New projects do not need name discovery;
  a compatibility fallback keeps legacy `applicationError` / `toHTTPError`
  projects working until they migrate.
- Auth and RBAC inbound templates use `httpx.*` for every success and
  `apperror.Translate` for every sentinel.
- Raw `c.JSON(...)` and `c.Status(...)` are not allowed in generated inbound
  adapters (tests and the shared `httpx` package are excluded).

### 4. Document the contract once

Add `docs/architect/http-contract.md` to generated projects with the table
above, the error-code rules, and the rule that handlers call `httpx.*` and
`c.Error(appError(err))` rather than writing JSON themselves. Update
`README.md` (“Error payload” becomes “HTTP payload contract”), `patterns.md`,
`architecture.md`, `AGENTS.md`, and the generated skill to link to that file
instead of restating fragments.

### 5. QA gate is executable before the refactor

`tests/qa/http-contract.test.mjs` generates a temporary project and writes Go
oracle tests into it. It has two tiers:

- **Regression tier (must be green before and after):** real Gin router and
  `httptest.NewServer` requests asserting list/item/create/delete/404/400
  shapes, the error middleware envelope, and the pagination envelope.
- **Target tier (red before, green after):** Go tests for
  `apperror.Translate` and `httpx.OK/Created/NoContent/Page`, plus static
  checks that every generated module/auth/RBAC inbound adapter uses the
  generic helpers and has no raw writer or `toHTTPError`.

The QA harness is an external oracle: it does not rely on tests shipped by the
implementation, so a template cannot “pass” by deleting its own assertions.
`QA_KEEP=1` preserves the scratch project for inspection.

## Risks / Trade-offs

- **Large mechanical template diff.** Auth and RBAC have about 30 response
  sites. The QA oracle covers the module path behaviourally and the auth/RBAC
  path statically; generated-project `go test ./...` covers compilation.
- **Auth/RBAC code-based errors do not fit a pure sentinel table.** They keep a
  small code→status table, but still use `apperror.New` and `Translate` for the
  common path. The important removal is the duplicated `toHTTPError` switch,
  not every line of policy.
- **`httpx` imports `pagination`.** This is a shared-to-shared dependency. It
  is acyclic today; if `pagination` ever needs `httpx`, `Page` moves to
  `pagination` as a method and the handler still calls one helper.
- **Existing generated projects do not get the fix.** Templates only affect
  new generations. Document this in the changelog; a project can copy the
  helpers or regenerate.
- **Static checks can be too strict for hand-written modules.** The QA oracle
  inspects only generated fixtures. The runtime `check` command is not changed
  to fail on raw `c.JSON`; that would reject intentional custom handlers.

## Migration Plan

- New generated projects receive the helpers, tables, and docs.
- Existing generated projects are unaffected until regenerated. The changelog
  states that the wire format did not change and lists the files to copy for a
  manual adoption.
- Rollback: revert the templates and remove the `test:qa` script; the generated
  wire format is unchanged, so no data migration is required.

## Open Questions

None. The wire-envelope choice and CLI JSON scope are explicitly out of scope
and recorded in `proposal.md`.
