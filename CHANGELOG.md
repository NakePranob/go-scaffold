# Changelog

## Unreleased

### Added: read-only module surface and JSON plan

`generate module --surface read` creates a module that owns a table but
exposes a read-only repository port and adapter with list/get, no write
methods, and no write routes. `generate method` accepts only
`--type get --get-mode all` for this surface; `go-scaffold check` enforces the
read-only boundary.

`generate module --plan` prints the intended files and migrations as JSON and
writes nothing. It is the dry-run counterpart to a real generation and works
with every surface.

### Changed: one generic HTTP response and error pattern

Generated inbound adapters now write success through
`internal/shared/httpx`: `OK`, `Created`, `NoContent`, and `Page`. Errors go
through `apperror.Translate`, which maps an ordered list of
`apperror.Rule` values and falls back to the shared internal-error envelope.

The generated module, auth, and RBAC handlers no longer carry separate
`applicationError`/`toHTTPError` switches or write JSON at each call site, and
`generate method` emits the same helpers. The wire format did not change:
single resources are bare objects, lists keep `{data, limit, offset, total}`,
deletes stay `204`, and errors keep the `{"error": ...}` envelope.

New projects also receive `docs/architect/http-contract.md`, the single
reference for the success, collection, error, and request-ID rules.

### Changed: one repository-wide agent skill

`create` now writes a single `.agents/skills/go-scaffold/SKILL.md` at the
repository root for every package, instead of a package-scoped name such as
`go-scaffold-services-api`. The skill locates the target package's
`go-scaffold.config.json`, `AGENTS.md`, and `docs/architect/` before acting,
so package-specific paths stay in the package docs.

An existing skill whose content differs — a hand edit, or a package generated
by another CLI version — is reported and left untouched instead of being
silently overwritten. `create` writes no project files before that check
fails.

## 0.14.0

`go-scaffold check` is stricter. A project that passed under 0.13.0 can fail
under this release if it already broke a layer rule somewhere the old check did
not read. Projects generated by go-scaffold are not affected: every profile,
`add auth`, and `add rbac` emit the same files as 0.13.0 and pass with no
warning. Run `go-scaffold check` after upgrading and fix what it names.

### Changed: `check` reads every adapter folder

- Inbound rules used to apply only to `adapters/inbound/http`. They now apply
  to every Go file under `adapters/inbound/`: `ws/`, `grpc/`, or a file placed
  directly in `inbound/`. Importing GORM, `internal/platform`, a sibling
  module, or the module's own outbound adapter from any of them now fails.
- A Go file outside every known layer, such as `adapters/kafka/` or
  `internal/app/<module>/helpers/`, used to be skipped entirely. `check` now
  prints a warning naming its folder and applies the sibling-module rule to its
  files. The folder itself does not fail the check.
- Outbound rules already covered every folder under `adapters/outbound/`; that
  is unchanged.

### Fixed: an import of the package itself is now caught

The forbidden-package patterns ended in `/`, so `internal/shared/tx/sub`
matched but `internal/shared/tx` did not. These imports now fail:

- application and ports: `internal/shared/{apperror,httpx,middleware,tx,dberr}`
  and `internal/platform`
- outbound: `internal/shared/{httpx,middleware}`
- domain: `internal/shared` and `internal/platform`

A package that only shares a prefix, such as `internal/shared/txlog`, is not
matched.

### Added: the `none` module surface

- `generate module <name> --surface none`, or "No database" under Advanced in
  the wizard, generates a module that owns no table. It keeps `domain/`, the
  application service or command/query handlers, the HTTP handler, and a
  `composition.go` whose `NewHandler` takes no database handle. It has no
  `ports/repository.go`, no DTO files, no `adapters/outbound/postgres/`, and
  no migration, and `check` does not require them for this surface.
- `generate module` accepts `--surface <minimal|crud|none>`, which can be
  combined with `--cqrs` but not with `--profile` or `--full`.
- `create --module-surface`, `modules.<name>.surface`, and
  `architecture.defaultModuleSurface` accept `none`. The default is still
  `minimal`.
- `generate method` refuses a `none` module and says to add the route by hand.
- `undo module` removes a `none` module's wiring and no longer mentions a table
  it never had.

### Upgrade notes

- go-scaffold 0.13.0 and earlier reject a `go-scaffold.config.json` that
  contains `"surface": "none"`. Upgrade the CLI for everyone working on a
  project before generating a `none` module in it.
- Two CLI error messages name the new flag: `--profile cannot be combined
  with --surface, --full, --no-full, or --cqrs`, and the non-interactive
  missing-flag list now reads `--profile, --surface, or --full/--no-full`.
